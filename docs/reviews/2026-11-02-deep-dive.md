### What exists today

### Concrete defects

1. **Three competing coach navigators** — sidebar + dock + header-equivalent public links (via dock) plus FAB and ⌘K. Simeon’s “bloated / overdone” read is accurate.
2. **Teams vs league team vs public `/teams`** — Showdown paste teams, drafted league roster, and public directory share language (“Teams”).
3. **`/calc` exits the dashboard shell** — sidebar disappears; worse on PWA standalone.
4. **Command palette is thin** — four links; doesn’t mirror weekly match / draft / FA.
5. **Admin League mega-submenu** — hard to scan; hash anchors (`#teams`) mixed with real routes.
6. **Admin still shows public `SiteHeader`** — double top chrome + forced `!top-16` sidebar.
7. **Coach vs admin collapse modes differ** (icon vs offcanvas).
8. **`StartNewSeasonWizard` wired but never opened** from sidebar (dead UI state).
9. **Dock touch targets** are icon+10px label, often under 44px; overlaps music player + AI FAB on mobile.

### Proposed consolidated model (option for Matt/Simeon)

**Principle:** one primary nav per surface. Optional mobile bottom bar only if it maps to 3–5 coach jobs, not nine public links.

## 2. PokeAPI and pokenode-ts usage

### Inventory (compact)

| Path | Mechanism | Where |
|------|-----------|--------|
| `pokenode-ts` `PokemonClient` | Live API (often official) | `lib/pokemon-api-enhanced.ts`, `lib/pokemon-api.ts`, `lib/draft-board-display-resolver.ts`, `app/pokedex/page.tsx`, admin pokemon route, catalog hydrate fallback |
| Direct `pokeapi.co` / `POKEAPI_BASE_URL` | `fetch` | `lib/pokemon-details.ts`, Edge `sync-pokemon-pokeapi`, `sync-pokepedia` |
| DB cache | `pokemon_cache`, `pokepedia_pokemon`, Showdown/`pokemon_unified` | Server reads, pokepedia GraphQL proxy |
| Redis | Homepage only | Not catalog |
| Sprites | GitHub PokeAPI sprites + optional Supabase bucket; `next/image` with **`images.unoptimized: true`** | `pokemon-sprite.tsx` |

### Problems

1. **Multiple read stacks on one page** — `/pokedex` can hit `PokemonClient`, raw details fetch, and DB adapters in one session.
2. **Client `pokemon-api-enhanced` skips DB** — every browser session can re-hit PokeAPI (rate-limit + latency).
3. **Two overlapping tables** — `pokepedia_pokemon` vs `pokemon_cache` with merge logic in `pokemon-utils`.
4. **No shared Next `fetch` revalidate policy** for Pokémon payloads.
5. **Draft board cache-miss → live pokenode-ts** with batch delay — fine as write-through, bad as primary UX path.
6. **Sprites unoptimized** — large mobile payloads; CDN/GitHub dependency.

### Recommendations

1. **Make pokepedia (or one merged catalog table) the only public read path**; Edge/cron + admin bootstrap remain the **write** path.
2. **Ban client-side `PokemonClient` / pokeapi.co** in app routes; server components / Route Handlers only.
3. **Collapse `pokemon-details` + enhanced + utils** into one server module with Redis/DB TTL.
4. **Self-host or Blob sprites** for top ~900 league-relevant forms; keep `next/image` but enable optimization or use a CDN with fixed sizes.
5. **Rate-limit guard:** never call official API from request path without `pokemon_cache` hit-or-enqueue.

**Matt option:** Is public Pokédex a first-class league tool, or a secondary reference? If secondary, freeze features and prioritize catalog reliability over chat.

### Lean AI strategy (proposal)

Help coaches and Matt where prose or grounded retrieval beats forms:

1. **Rules Q&A** — league docs / FA windows / Tera / points (RAG over static docs).  
2. **Matchup prep** — battle-strategy with roster + opponent (capped tokens).  
3. **Draft help** — budget-aware suggestions in draft season only.  
4. **Summaries** — weekly recap + trade/FA digest for Matt (batch, not chat).  
5. **Result assist** — regex first → Jev classify → LLM parse only on medium/low confidence.

**Guardrails:** default MCP off unless tool needed; per-route daily budgets; log model + tokens; never auto-write competitive rows while sheet sync owns Season 7.

**Matt options:** Keep global FAB vs context-only “Help” on This week / Draft; whether FA AI may propose drops before app is SoT.

## 5. Jev decision model fit

### What Jev is (for this doc)

TypeSafe **System One** model (launched Sep 2026). It does **not** generate text. Given `state` (text/JSON), it answers typed questions: **choice** (≤255 options + probabilities), **score** (2–10 level rubric), **noul** (P(yes)). ~**$0.042 / M input tokens**, output free. Via TypeSafe API, OpenRouter Decisions (`typesafe/jev-1.13`), Vercel AI Gateway, Cloudflare. Caveats: weaker on fine-grained quality judgments; tune binary thresholds; calibration varies.

### Where it fits this league

| Use | Question shape | Why Jev beats LLM |
|-----|----------------|-------------------|
| Discord #battle triage | `noul`: is this a result post?; `choice`: which match / winner | Cheap pre-filter before regex/LLM; complements 37/38 fixture parser |
| In-app help routing | `choice`: standings / roster / FA / draft / calc / human | Replace mega-menu guessing |
| Rules flags | `noul`: likely FA-window / Tera / points violation | Human-in-the-loop admin queue |
| Coach applications | `score`: readiness rubric; `noul`: spam? | Triage, not auto-approve |
| Moderation | `noul`: off-topic / toxic in league channels | Soft gate |

### Where not to use it

- Writing recaps, strategy prose, or draft essays (use LLM).  
- Exact standings / SOS / seed math (deterministic SQL).  
- Final match write without human/sheet when confidence is soft.  
- Fine aesthetic UI copy or “is this team good?” quality taste.

### Deployment sketch

```
Discord post / user query
        │
        ▼
 lib/jev/client.ts  ──►  OpenRouter Decisions or TypeSafe System One
        │                   TYPESAFE_API_KEY or OPENROUTER_API_KEY
        │                   (Infisical → Vercel env; never repo)
        ▼
 thresholds (noul ≥ 0.85 auto-queue flag; 0.55–0.85 review; <0.55 ignore)
        │
        ▼
 existing regex reconcile  ──►  optional LLM parse-result only if needed
```

- **Logging:** store `{ input_hash, questions, probabilities, threshold, action }` for tuning.  
- **Pilot dataset:** the **37 matched / 1 miss** Discord result fixtures in `lib/discord-results` acceptance tests — measure Jev vs regex on “is result?” and “winner choice”.  
- **Fallback:** if Jev errors/timeouts → current regex path unchanged.  
- **Cost estimate:** ~500–2k tokens/post × ~50 posts/week ≈ negligible ($0.01/week order); tuning runs on 37 fixtures ≈ cents.  
- **First pilot:** Discord result **noul(is_result_post)** + **choice(winner among two scheduled teams)**; never write matches; only enrich admin Discord results flags.

**Matt options:** Approve Discord pilot only; or also route in-app Help with Jev before any LLM call.

## Top findings (5 per section)

### §1 Nav
1. Coach has sidebar + 9-item dock + FAB + thin ⌘K — too many systems.  
2. “Teams” means three different things.  
3. Admin keeps public header; collapse mode differs from coach.  
4. `/calc` leaves the shell.  
5. Consolidation should start from Home / My team / This week / Showdown / Draft / Account.

### §2 PokeAPI
1. Client paths bypass DB and hit live API.  
2. pokepedia vs `pokemon_cache` duplication.  
3. `/pokedex` stacks multiple clients.  
4. Redis unused for catalog.  
5. Single server read path is the fix; sync stays write-only.

### §3 PWA
1. Offline fallback may miss `/offline` on first fail.  
2. Three bottom floats fight thumbs.  
3. Manifest shortcuts are fan pages, not coach jobs.  
4. Safe-area uneven.  
5. Coach phone flows are usable but cognitively heavy.

### §4 AI
1. Useful: draft, battle prep, recap, gated parse.  
2. Dead weight: orphan coach route, pokedex-v2 duplicate.  
3. MCP-on-by-default burns tokens.  
4. Lean strategy = rules Q&A + prep + summaries; not competing writers.  
5. Pair parse-result with cheaper classifiers.

### §5 Jev
1. Strong fit: Discord triage, routing, soft rule flags.  
2. Bad fit: prose, standings math, auto-scoring matches.  
3. Pilot on 37 Discord fixtures, flags only.  
4. Keys via Infisical/Vercel only.  
5. Cost is noise vs current LLM chat.
